CASE STUDY 03 / WORKFLOW AUTOMATION · DATA MIGRATION

Drive-to-Notion Migration Pipeline

A Google Apps Script pipeline that extracts supported document content, creates structured Notion pages and preserves links to original Google Drive files.

TechnologyGoogle Apps Script · Google Drive API · Notion API · Google Sheets
Project statusUsed operationally · Error handling documented

The challenge

The objective was to migrate a substantial document corpus from Google Drive into a more structured Notion environment without losing the relationship between migrated content and its original files. The workflow also had to accommodate Apps Script execution limits and differences in document and database schemas.

Workflow architecture

  • Retrieve documents to process from Google Drive.
  • Extract text from supported formats, including PDF and DOCX. Some formats were temporarily converted to Google Docs for extraction.
  • Create corresponding structured pages in Notion and preserve a reference to the original Drive file.
  • Move processed source files into a separate folder for later classification.
  • Use batch processing, timed resumption and Google Sheets execution logs to support runtime management and troubleshooting.

Format handling and related workflow

PNG and JPG images were retained as attachments or references; the documented workflow did not perform OCR on those images. A separate process migrated legacy nested Notion pages into a database-based structure; it was not a stage of the Drive-file pipeline.

Operational use and constraints

The pipeline was reportedly used for approximately eight months and processed tens of thousands of files comprising multiple gigabytes. These figures are user-reported, not independently audited. Execution logs record Notion API validation errors, including filenames exceeding the 100-character limit for a file-name property. The logs do not establish that every historical error was eliminated. Duplicate detection was intentionally outside scope because it was not required for the use case.

Skills demonstrated

Workflow automationREST API integrationDocument-content extractionStructured page creationSource traceabilityBatch processing and timed resumptionExecution logging and API error diagnosis
Key takeaway

Migration is more than copying content: it requires extraction, structured record creation, source traceability and runtime-aware processing.
